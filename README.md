# GDR 대진표 · 경기 기록

테니스 모임의 복식 대진 편성과 경기 기록을 관리하는 웹 앱입니다.

[사이트 열기](https://felix-mr.github.io/gdr-tennis/)

## 주요 기능

- 참석자와 게스트, 모임 날짜·시작·종료 시간 설정
- 개인별 경기 수 배분과 복식 대진 자동 편성
- 대회 준비를 위한 고정 페어 설정
- 먼저 마무리하거나 나중에 시작하는 경기 순서 선호 반영
- 개인별 경기·휴식 라운드 조회
- 경기 점수 입력과 기간별 순위·개인 기록 조회
- 대진표와 경기 기록 이미지 저장·공유
- CSV 내보내기와 JSON 백업

## 대진 편성 원칙

참석 인원, 코트 수, 모임 시간을 기준으로 개인별 경기 수를 배분합니다. 자동 배분에서는 개인별 경기 수 차이를 최대 한 경기로 맞추며, 같은 라운드에 중복 출전하지 않도록 합니다.

경기 수와 시간 조건을 지키면서 연속 휴식을 줄이고, 팀 구성을 균형 있게 편성합니다. 파트너와 상대 조합이 한쪽으로 치우치지 않도록 당일 배정과 최근 대진을 참고합니다.

고정 페어는 두 명 모두 참석하면 모든 경기에서 함께 출전합니다. 새 페어 등록 시 페어 유지가 켜지며, 사용자가 직접 끌 수 있습니다. 참석 인원·개인 경기 수 조건상 고정 페어를 유지한 대진을 찾지 못하면 자동으로 해제하지 않고 설정 조정을 안내합니다. 경기 순서 선호를 함께 반영합니다. 조합 분산에 관한 선호는 참석 인원과 경기 수 등 운영 조건에 따라 가능한 범위에서 적용하며, 모든 선호를 항상 충족하는 것은 아닙니다.

고정팀은 상대 파트너가 바뀌어도 같은 선수를 다시 만나면 반복으로 계산합니다. 경기 수·고정 페어·휴식 및 경기 격차 조건을 지키는 후보에서 특정 상대에 몰리는 횟수와 전체 반복을 줄입니다. 참석 인원이 적거나 대부분 고정 페어인 경우에는 반복이 불가피할 수 있으므로 일률적인 1회 제한을 두지 않습니다.

확정 전 미리보기에서 개인별 경기 수와 휴식 라운드를 확인할 수 있습니다. 기존 확정 대진은 새로운 대진 생성으로 변경되지 않습니다.

미리보기의 `대진 직접 수정`에서 선수 자리 교체·팀 이동·같은 라운드 휴식자 투입을 할 수 있습니다. 수정은 되돌리거나 처음 대진으로 복원할 수 있으며, 적용 후 별도로 확정·저장해야 공유됩니다. 중복 출전·최소 2경기·고정 페어 분리 여부를 검사합니다. 수정으로 생기는 경기 수 차이·파트너 반복·경기 사이 연속 휴식은 표시하여 확인할 수 있습니다. 확정된 대진은 이 기능의 수정 대상이 아닙니다.

편성 참고 성적은 같은 반기를 기본으로 하며, 충분한 기록이 있는 현재 분기 흐름을 함께 고려합니다. 경기 수와 확인 가능한 참석률이 낮은 기록은 신뢰도를 낮춰 초기 설정을 더 유지합니다. 참석 자체를 실력 점수로 계산하거나, 날짜가 없는 누적표에서 참석률을 추정하지 않습니다. 이전 집계와 실제 경기의 중복을 차감하고 다른 반기·당일·미래 자료를 제외합니다. 평가값은 회원 화면에 표시하지 않습니다.

## 경기 기록

클럽원 4명 이상이 참석한 모임만 공식 기록에 반영합니다. 게스트는 이 인원 기준에서 제외하며, 개별 경기의 클럽원 수가 아닌 모임 전체 참석 명단으로 판정합니다. 클럽원 4명 미만 모임의 대진·점수도 보관하고 대진표 이미지로 공유할 수 있지만, 순위·승률·개인 상대 전적·참석률 및 다음 편성의 참고 이력에는 반영하지 않습니다. 참석 명단이 없는 기존 기간 집계는 인원을 추정해 분할하거나 삭제하지 않습니다.

- 경기 시간은 30분 단위입니다.
- 점수는 0~99의 정수로 입력하며, 저장한 0:0은 무승부입니다.
- 미입력 경기는 순위 집계에 포함하지 않습니다.
- 승리 3점, 무승부 1점, 패배 0점으로 집계합니다.
- 같은 승점은 공동 순위로 표시합니다.
- 기간별 경기 수·승무패·승률·득실과 실제 경기의 파트너·상대 조합을 조회할 수 있습니다.
- 이전 집계와 실제 기록이 겹치는 경우 중복 합산을 방지합니다.

## 저장과 Firebase 설정

Firebase 설정이 없으면 현재 브라우저의 로컬 저장소를 사용합니다. 다른 기기와 공유되지 않으므로 JSON 백업으로 보관할 수 있습니다.

Firebase 설정이 있으면 Firestore의 공유 기록을 사용합니다. 연결 실패 시 로컬 저장소로 자동 전환하지 않으며, 점수 수정 시 버전을 확인해 다른 사람의 변경을 덮어쓰지 않도록 합니다.

1. `.env.example`을 `.env.local`로 복사합니다.
2. Firebase 웹 앱의 `apiKey`, `authDomain`, `projectId`, `appId`에 해당하는 설정을 입력합니다.
3. 기존 규칙과 충돌하지 않도록 `firebase/firestore.rules`의 앱 관련 규칙을 반영합니다.
4. 앱을 재시작하고 공유 기록 연결을 확인합니다.

`.env.local`과 원본 기록 파일은 공개 저장소에 포함하지 않습니다. 공유 기록에는 모임 정보, 라운드별 대진, 경기 결과를 분리해서 저장합니다. 게스트는 모임별로 식별하며 다른 날짜의 동일한 이름이나 ID를 자동으로 합치지 않습니다.

대진 취소는 확인 문구와 대진 버전을 검사합니다. 취소하면 해당 날짜의 대진과 점수가 삭제되므로 확정 전 내용을 확인해야 합니다.

## 배포

GitHub Pages는 `gh-pages` 브랜치의 빌드 결과를 게시합니다. Firebase 연결 설정을 준비한 뒤 다음 명령을 사용합니다.

```sh
npm run deploy
```

배포 스크립트는 연결 설정을 확인하고 빌드 결과만 게시합니다. 사이트 배포와 Firestore 규칙 반영은 별도입니다.
